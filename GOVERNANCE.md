The project uses a maintainer-led open-development model.

## Roles

- **Users** run simulations and report evidence.
- **Contributors** submit code, tests, profiles, and documentation.
- **Reviewers** reproduce behavior and review an engineering area.
- **Maintainers** triage, merge, release, and enforce project policy.

Replace `@OWNER` with the initial maintainer when publishing.

## Decision process

Routine changes use pull-request review. Significant changes require an issue and architecture decision record.

Decisions should record:

- engineering problem;
- constraints;
- alternatives;
- trade-offs;
- safety and recovery impact;
- verification plan;
- final rationale.

Maintainers seek technical consensus. When consensus is not possible, the maintainer records the decision and rationale publicly.

## Release authority

Maintainers create releases only after required automated checks and profile-specific manual verification are complete.
